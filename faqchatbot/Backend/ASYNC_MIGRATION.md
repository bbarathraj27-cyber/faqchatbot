Async Migration Guide

Goal
- Incrementally migrate I/O-bound code to async/await to improve concurrency and reduce blocking in FastAPI endpoints and background tasks.

4. Replace blocking calls in async paths with either async clients or run blocking functions in threads via `asyncio.to_thread`.
5. Update FastAPI endpoints to `async def` and `await` async functions gradually.

Migration patterns & examples

1) Async HTTP fetcher (scraper)

Sync (original):
```py
import requests

def fetch_html(url: str) -> str:
    r = requests.get(url, timeout=...) 
    r.raise_for_status()
    return r.text
```

Async (httpx):
```py
import httpx

async def async_fetch_html(url: str, client: httpx.AsyncClient | None = None) -> str:
    own = False
    if client is None:
        client = httpx.AsyncClient(timeout=...)
        own = True
    try:
        r = await client.get(url)
        r.raise_for_status()
        return r.text
    finally:
        if own:
            await client.aclose()
```
Keep a sync wrapper for compatibility when called from worker threads:
```py
def scrape_faq_page(...):
    return asyncio.run(async_scrape_faq_page(...))
```

2) Running a blocking function from async code

If a library has no async API (e.g., embedding client or legacy function), offload it to a thread:
```py
embeddings = await asyncio.to_thread(embed_texts, texts)
```

4) Pinecone / external SDKs without async APIs

Wrap blocking SDK calls in `asyncio.to_thread` in new `async_*` convenience functions so callers can `await` them without blocking the event loop.

5) FastAPI routes

- Prefer `async def` for request handlers that perform I/O.
- `await` async service functions directly. Avoid calling `asyncio.run` inside request handlers.

6) ThreadPools & background workers

- If you already use `ThreadPoolExecutor` for concurrency, you can either
  - Keep thread-based concurrency and call sync functions there, or
  - Convert workers to run async code via `asyncio.run` per task or run an async worker loop.

Notes & pitfalls
- Do NOT call `asyncio.run` from inside an active event loop (e.g., inside an async FastAPI route). Use direct `await` or `asyncio.to_thread`.
- Keep blocking/CPU-bound work off the event loop (use threads/processes).
- Migrate incrementally: add `async_*` versions first, update a small set of callers, run smoke tests, then expand.
